# MVP-091 — PDF a proveedores y seguimiento privado por WhatsApp

02/11/2026 · Issue #393 · entorno exclusivamente `cotironda-piloto` (`ilggkalaafhtiysyzlmg`). No publicar producción ni tocar DEV.

## Contrato aprobado
El arquitecto envía **una sola vez** su pedido de texto por WhatsApp (incluye localidad de entrega). Cotironda extrae las líneas admitidas, selecciona únicamente proveedores de categoría registrada en la zona y envía a cada uno **una solicitud PDF propia, profesional y anónima**; el proveedor responde por WhatsApp, y el original se conserva sin alterar. El arquitecto recibe un mensaje con un enlace único para ver **cuántas** cotizaciones llegaron. Ningún presupuesto, identidad o precio es visible al cliente ni por API hasta cumplido el plazo de cuatro días (configurable dentro de 3–7). No hay botón de adjudicación; tras el cierre comercial y la comparabilidad auditada se habilitan hasta dos finalistas. No anunciar posiciones engañosas.

**Exclusión comercial explícita:** el PDF **no incluye** frases o requerimientos sobre IVA, fletes, adicionales, descuentos ni condiciones de venta. Solo identificación Cotironda, código, localidad, vencimiento, descripción y cantidades, y «Respondé por WhatsApp con tu presupuesto». Esta regla no quita información de los presupuestos que envían los proveedores: sus originales se deben conservar con absoluta fidelidad.

## Implementación de esta rama

1. `supabase/functions/cotironda-piloto-whapi/request-pdf.ts`: generador PDF A4 determinista puro TS, con validaciones estrictas, 1–8 materiales, cantidad decimal precisa, unidades argentinas, límites de caracteres, sin dependencia externa ni datos personales. La fuente son SOLO `request_lines` del snapshot SQL confiable. Se conserva el documento de ejemplo descargable para revisión estética en el chat (no se versiona como producción).
2. `supabase/piloto/mvp091_next_round_limited_dispatch.sql`: una ventana corta de operador para una sola ronda nueva; solo el arquitecto enrolado, máximo Ailín/Nahuel, únicamente familias cemento/hidrófugo, zona La Plata, opt-in vigente, sin oferta previa. Se mantiene doble check SQL en claim y autorización inmediatamente antes del envío, sin reintentos de estados `leased/uncertain` y sin cambiar flags automáticamente. Esta limitación específica es TEMPORAL hasta confirmar catálogos reales.
3. `supabase/piloto/mvp091_buyer_tracking_pdf_guard.sql`: token fuerte de 32 bytes emitido desde Edge, almacenado solo como hash SHA256 en PostgreSQL (tabla RLS sin acceso a roles de API); se vincula con el `source_hmac` del mensaje real y con el HMAC autenticado del chat del comprador. Requiere consentimiento, ronda nueva creada hace menos de 5 min y salida habilitada. Ledger idempotente marca emisión intentada como `api_accepted` o `uncertain`, sin reenvío ciego.
4. `cotironda_piloto_tracking_status_mvp091` devuelve solo estado, `received_count` y fecha límite mientras la ronda está abierta. **No SELECT de textos originales a cliente, nunca.** Al cierre retorna únicamente ofertas específicamente aprobadas dentro de `anonymous_offers_mvp091`, atadas a la última revisión y aprobadas por operador, sin ningún nombre/contacto real. Si no existen, muestra «Esperando verificación». La selección/revelación automática de finalistas no está implementada todavía, como gate separado.
5. `supabase/functions/cotironda-piloto-seguimiento/index.ts`: página de lectura sin login adicional, con token en FRAGMENTO `#` de la URL (no va a las URLs HTTP ni a logs de query). El navegador envía token mediante POST HTTPS solo a su mismo origen, backend verifica hash y consentimiento. HTML no trae nombre ni precio; CSS inline; CSP, DENY frame, no-referrer y no-store; texto del servidor se asigna por `textContent`, jamás HTML de proveedor.
6. `cotironda-piloto-whapi/index.ts`: en un mensaje `recorded` del arquitecto emite un solo enlace para esa ronda y envía por WhatsApp al chat AUTENTICADO del comprador. Luego para las invitaciones, al tomar lease verificable, obtiene snapshot, genera PDF y lo envía como documento privado por `POST /messages/document` con media Base64, no URL pública. **Un único documento por invitación**, nunca PDF+texto duplicados. Timeout/error queda `uncertain`, no se reintenta sin conciliación.
7. `tests/unit/mvp091-solicitud-pdf.test.mjs` y `tests/unit/mvp091-buyer-tracking.test.mjs` + `supabase/piloto/mvp091_smoke_rollback.sql`: PDF 8 artículos, formato cantidades, rechazo de fuentes inseguras, token, RLS, anti-filtración, dos proveedores/una sola ronda, resguardo antes del plazo. Migración + SQL smoke en una transacción con rollback aprobó en PG17 del proyecto PILOTO (el resultado NO persistió ningún pedido de prueba).

## Precauciones y tareas pendientes
- La ventana de una sola ronda NO se inserta/activa en la migración. Debe habilitarse por un operador con cupo de prueba y consentimientos reales, después de auditar CI e instalación Edge. El flag de salida SQL permanece apagado hasta esa auditoría.
- Whapi API aceptada **no demuestra que el PDF se haya entregado** al destinatario. Obtener confirmación con Ailín/Nahuel.
- El portal de estado no muestra presupuestos al comprador antes del vencimiento **ni siquiera desde DevTools**; el contador proviene de SQL seguro. Después del cierre, mostrar fuente solo tras revisión de anonimización sin eliminar renglones. Falta el proceso automático que genera ese original íntegro en formato propio y la decisión económica determinista de hasta dos finalistas. El cron actual **solo cierra la ronda**, no hace ese ranking ni notificaciones.
- Los proveedores pueden responder por WhatsApp en texto hoy. PDF, Excel, Word, fotos y audios recibidos **todavía no se extraen como cotización automáticamente** en esta instancia del piloto; no afirmar que esos formatos ya funcionan E2E.
- El remitente del enlace necesita ser el chat autenticado que originó una ronda; no aceptar un destinatario elegido por una URL o mensaje del comprador. Limitar costos por llamada Whapi y validar formato `data:application/pdf` con API real antes de expandir a rubros.
- El mapa de destinatarios en Edge Secrets todavía contiene solo Ailín/Nahuel. Para agregar contactos sin modificar JSON por persona, reemplazarlo por el registro cifrado y onboarding administrador de Issue #392. No duplicar la infraestructura D068.
- Ninguna modificación a `main`, Vercel Production, dominio, Supabase DEV u otro proyecto.

## Prueba de producto objetivo
El arquitecto manda nuevo pedido con `Entrega: La Plata`, `20 bolsas cemento CPC 50 kg` y `5 litros hidrófugo`. Se crea **otra** ronda válida de cuatro días, se envían 2 PDF a los proveedores, se entrega enlace privado al comprador, los vendedores responden a sus tiempos. El enlace muestra 0/1/2 cotizaciones, sin abrir ofertas antes de fecha. El cierre automático existente marca la ronda `closed`. Los contenidos se habilitan solo tras revisión de identidad y fidelidad, no se comunica un vencedor sin comparación real.
